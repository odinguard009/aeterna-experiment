# Aeterna session runner

The repo CLAUDE.md is the source of truth; this skill only orders its steps. Do not re-read CLAUDE.md (it loads automatically). Session form since 2026-10-20: one main session, no team, no worktrees, no subagents except the read-only player-view pass; no size or token limit (chain mode: End step 6).

## Start (one call each, condensed output)
0. Auto mode (rules: `docs/ai/next-session-prompt.md`). Scheduled runs: right after `add_repo` and BEFORE the clone run the `session_gate.sh ... check` one-liner from their prompt; anything but GO = end the run at once. Manual sessions skip `check`. The owner commands `otomatis on|off|status` run the same one-liner with `on`, `off` or `status` (no clone) and end there.
1. `add_repo` odinguard009/aeterna-experiment (push access), then ONE light sparse clone exactly as CLAUDE.md says, then `register_repo_root`.
2. `bash tools/session_start.sh` (prints chain-stop, open handoff, last Regression, Next line, counts). `CHAIN-STOP` = stop unless the owner is present and has answered (then delete `docs/ai/chain-stop.md`). `OPEN HANDOFF` = continue from it first. Exit 3 / `OVERLAP` = another session is running: stop and tell the owner. Then mark the session: scheduled `bash tools/session_gate.sh lock`, manual `bash tools/session_gate.sh manual` (exit 3 = an auto session holds the lock: stop). If the gate call is refused or errors, say so once and continue (marks expire: LOCK 5 h, MANUAL 3 h).
3. Schedules are never touched by sessions (`create_trigger`, `update_trigger`, `delete_trigger`).
4. Read `docs/ai/roadmap-open.md`. The item comes from the lane that `session_start.sh` prints as `LANE K|U/I` (order: phase F, S1 Standard Magic, the whole U/I queue, then K with Standard first, owner 2026-10-21; fallback to the other lane when the lane has no ready item; rules: item L of `roadmap-open.md`). Take that lane's next item and open with ONE Indonesian line: `Ver. X.Y.Z (rencana) - gunakan model <Opus|Sonnet> - <scope> - Token awal: <total_tokens at the start>`. Opus for engine, protocol and compiler work; Sonnet fits docs/cleanup and card bundles that only write effect JSON with existing actions. If the running model differs, say so once and continue.
5. Player-view pass (skill `bs-playwright-tester`, read-only subagent, started at once) only in a session that makes a backup (End step 3) or changes the UI.
6. Card-session prep: `python3 tools/pack_plan.py` sizes the packs; main runs one scratch recompile itself (`tools/lever_report.py` or strip-and-recompile under `build/` or the scratchpad, never `data/` or the engine). Rules source: skill `bs-wiki-rules` (`python3 tools/wiki_rules.py --for "<blocker>"`) when the blocker has no `prep.rules` in `data/glossary/mechanics.json`; main does it itself. Results go into `mechanics.json` and `roadmap-open.md` in the last commit.

## During
- Previous Regression (printed by `session_start.sh`): `failure` = fix it first (a `fuzz` failure: download artifact `fuzz-cases`, commit the case, fix it).
- Per task: test/scenario first for a new mechanic, `npm run -s loop`, one commit (the first also bumps the version and opens the CHANGELOG heading, whose first bullet is `- Lane: K` or `- Lane: U/I` = the lane actually done; one version per session), then `git fetch origin main`, rebase and **push at once** (every commit is pushed, so a cut session loses at most one task).
- Promotion sessions read cards by `node tools/promotion_sample.mjs`; long runs (smoke over thousands of cards, 30-game sims) go to GitHub Actions, never waited for.
- Scheduled runs: before the next task run `bash tools/session_gate.sh switch`; OFF = no new task, go to End.
- A task that fails twice is dropped, named in the release notes and recorded in `roadmap-open.md` as `blocked (reason, date)`. If every open item is blocked, commit `docs/ai/chain-stop.md`.
- Lane K: per-task commits go to `wip/lane-k`; version bump, CHANGELOG and README happen once at the release per 50 new complete cards (`session_start.sh` prints the count).
- Usage / quota / rate-limit error: no retry; push what is committed (Lane K: `wip/lane-k`), handoff comment on issue #1 (done / next / failing seed), `bash tools/session_gate.sh unlock`, stop.

## End (in this order)
0. Docs into the last task commit: `node tools/mindmap_due.mjs`; only when due (every 3rd release) or the plan changed, update `docs/roadmap-data.json`. Always: the `**Next:**` line of CLAUDE.md and delete finished items in `roadmap-open.md`; `bash tools/release_docs.sh`; commit as `docs: vX.Y.Z release docs` and push (never amend a pushed commit; docs-only pushes start no CI).
1. `bash tools/release_docs.sh --end`: CI wait, Regression only when `tools/regression_due.sh` says DUE (not waited for; the next session reads it), backup when due, game file to `/mnt/user-data/outputs/aeterna-vX.Y.Z.html`, `node tools/session_end_check.mjs` (must pass; a `WARN` about the GitHub Release after CI = name its failing lines in the final message).
2. A mechanic finished this session gets `status: done`, `verified: true` in `data/glossary/mechanics.json` (before step 0).
3. Backup (every 5 releases, done by step 1 when due; a UI change keeps its own backup of the previous state). Keep the newest 3 `backup/v*` branches; older ones whose tip is on `main` are listed in `docs/ai/deleted-branches.md`; the owner deletes branches on GitHub (the proxy blocks deletion).
4. SendUserFile the game file (always) and `docs/roadmap.html` when the check prints `MINDMAP due` or `updated this release`; otherwise the final message says "Mind map: vX.Y.Z (next update in N releases)".
5. `bash tools/session_gate.sh done vX.Y.Z next=<Opus|Sonnet> start=<Token awal> sub=<sum of subagent_tokens> budget=<budget counter now>` (sub = the subagents' token use from their hand-back usage, owner 2026-10-21; 0 or left out when none ran) (copy both numbers, never subtract: the gate posts `tokens=`; item T, 2026-10-21) (add `rantai` when this session was a chain continuation; `unlock` on an early stop), then `bash tools/session_gate.sh rantai next`. Name the session "Ver. X.Y.Z". Short Indonesian summary: `Playable: X / 8,709, complete: Y` (`tools/unlock_report.py --line`), `Token terpakai: <Token awal minus total_tokens now>` (budget-counter difference incl. cache re-reads), `Mode otomatis: ON|OFF` (`session_gate.sh switch`), the `Mode rantai: …` line printed by `rantai next`, and the next model hint `gunakan model …` by the next item.
6. Chain mode: `rantai next` printed `GO` = send the summary, then start the next session in this chat at once from Start step 2 (`git fetch` + rebase, `session_start.sh`, a new `lock`/`manual` mark, new "Token awal", own version and release; its `done` carries `rantai`). Exit 3 on the mark = another session started: stop. `STOP` (or a gate error) = after the release, stop (questions go to a new session).
