# Docs index

One line per document. "Hand" = written by hand; "generated by X" = rewritten by that tool, never edit it. Start with `ARCHITECTURE.md`; where each kind of file goes: skill `bs-doc-convention`.

## Product
- `ARCHITECTURE.md` (hand): build, runtime, effect engine, card data pipeline, compiler, tests, session tooling, brand layer.
- `aegis-study.md` (hand): what to learn from Aegis (engine, CPU, UX ideas).
- `DESIGN.md` (hand): design system for the UI/UX overhaul (tokens, type, components, layout, do/don't); item U in `ai/roadmap-open.md`.
- `design/mockup-v11.html` (hand): approved UI/UX mockup (2026-10-18), the build target for sessions U1-U8; open in a browser.
- `design/mockup-v12.html` (hand): proposal mockup on v11 (owner 2026-10-22: friendliness update + animations; Aegis/CrossOver based). Not built — superseded by the v13 proposal below.
- `design/mockup-v13.html` (hand): expanded proposal on v12 (owner 2026-10-22 follow-up: device tabs Desktop/Phone, all phone screens, player profile + sign-in mock, card info page, uniform label casing, CrossOver-style animations with a performance budget, every button works; 11 desktop + 10 phone screens, 24 popups; all 47 mockup interactions pass). Not built — awaits owner approval.
- `design/ui-inventory.md` (hand): the complete UI list (every screen, dialog, strip, small piece) with status columns (shipped / v12+v13 proposal / deferred / open); the proposal source for mockup v12 (sections A–G) and v13 (sections H–L).
- `progress.html` (generated by `tools/build.mjs` via `tools/gen_roadmap.mjs`): progress page from the CLAUDE.md Roadmap, `ai/roadmap-open.md` and `CHANGELOG.md` + `CHANGELOG-archive.md`.
- `roadmap.html` (generated by `tools/gen_mindmap.mjs` from `roadmap-data.json`): mind map sent to the owner every session.
- `roadmap-data.json` (hand): mind map data (statuses, `updated`, `next`).
- `images/*.jpg` (generated by `tools/screens.mjs`): README screenshots.
- Root files: `README.md` (hand, front page), `CHANGELOG.md` (hand, release notes, newest first; v0.80.0 and older are in `CHANGELOG-archive.md`; GitHub Releases are made from it by `.github/workflows/release.yml`).

## Rules and mechanics
- `mechanics/*.md` (hand): one file per mechanic (source, page, decision, engine, tests, open points); started when a session touches the mechanic.
- `manual-notes.md` (hand): paraphrased notes from the official manuals, sources table at the top.
- `rules-coverage.md` (hand): rule-by-rule coverage table (input of `tools/rules_audit.py`).
- `rules/README.md` (hand): schema of the rules knowledge base (chunk ids, manuals, page references, SHA-256 fingerprints).
- `rules/kb.json` (hand, filled by `tools/rules_kb.py`): the official rule sections the engine cites, with paraphrases and fingerprints (`--list-cited` checks every citation, `--check` flags changed manual sections).
- `rules/standard-jp-1.1.md` (hand): Standard Rule Manual Ver.1.1 (JP) compared with the English 1.0 and the engine.
- `rules-audit-verdicts.json` (hand): audit verdicts (`checked` date, per-item verdicts; test D14).
- `reports/rules-audit.md` (generated by `tools/rules_audit.py`).
- `reports/effect-coverage.md` (generated by `tools/tag_effects.py`): glossary tags with card counts.
- `reports/mechanic-inventory.md` (generated by `tools/mechanic_inventory.py` from `data/glossary/mechanics.json`): every keyword and card kind in the pool with status, waiting/playable counts and prep (rules / data / lever); plan: `ai/roadmap-open.md` item K.

Generated reports live in `reports/` (first line names the tool).

## Card work
- `reports/unlock-report.md` (generated by `tools/unlock_report.py`): playable count and unlock estimates per pattern.
- `reports/priority-report.md` (generated by `tools/priority_report.py`): which cards first (Standard block A, then Eternal newest Saga first), playable per colour, shared texts, version marks.
- `build/compile-review.md` (not in git; generated by `tools/compile_effects.py --review build/compile-review.md`): why each staged card did not compile.
- `reports/pack-plan.md` (generated by `tools/pack_plan.py`): greedy order of compiler blockers, cards completed per step (upper bound), rule source per blocker.
- `reports/pack-plan-standard.md` (generated by `tools/pack_plan.py --block A --measure`): the same order restricted to Standard block A; the `New` / `Block A` columns are upper bounds, `Measured` / `Est. real` are what a scratch recompile actually produced.
- `reports/card-counts.json` (generated by `tools/unlock_report.py`): playable / complete / staged / total, the numbers the README build line and the tests read.
- `reports/fx-validate.md` (generated by `tools/fx_validate.mjs --staged`): effect-format validation for the shipped and the staged cards.
- `reports/cpu-bench.md`, `reports/cpu-bench.json` (generated by `tools/cpu_bench.mjs`): the CPU strength baseline the Regression `cpu-bench` job compares against.
- `audits/26RBS01.md` (hand): ledger of the A2 card-author pilot (v0.80.0) — why each 26RBS01 card stayed partial, by blocker.
- `reports/wiki-rules-index.md` (generated by `tools/wiki_rules.py --report`): Fandom keyword and Comprehensive Rules pages mapped to mechanics and blockers (links and counts only).
- `reports/compile-v2-report.md` (generated by `tools/compile_v2.py --report`): v2 first reasons, engine levers, cards with a single blocker.
- `saga-map.md` (hand): Saga -> set table and the Saga placement rule.

## Agent guides (`ai/`)
- `ai/code-map.md` (generated by `tools/code_map.mjs` on every build): top-level names per script part (`packages/engine/src`, `apps/web/src`).
- `ai/token-economy.md` (hand): how to spend few tokens; poll one-liners.
- `ai/release.md` (hand): tests and release gate.
- `ai/cards-and-rules.md` (hand): rules and card data sources and order of trust.
- `ai/effect-format.md` (hand): the effect JSON format (trigger + actions + conditions), the reference for every card edit; schema `../packages/engine/fx-schema.json`, validator `node tools/fx_validate.mjs` (a format change bumps the schema version).
- `ai/colour-version.md` (hand): checklist for a colour deck version.
- `ai/roadmap-open.md` (hand): open items and the session order.
- `ai/monorepo-plan.md` (hand): plan. Finished plans are archived in `ai/roadmap-archive.md`.
- `ai/compiler-v2-plan.md` (hand): clause-level effect compiler (target + action sentences), block A import, evidence and sessions.
- `ai/next-session-prompt.md` (hand): auto-mode rules and the scheduled prompt.
- `ai/owner-instructions.md` (hand): the owner's instructions in their words.
- `ai/deleted-branches.md` (hand): backup branches listed for deletion, restorable by SHA.
