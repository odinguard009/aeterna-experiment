# Token economy plan (user decision 2026-10-14: "no compromise on quality, but save tokens")

Goal: the same quality per release with far fewer tokens. Each rule says who does it.

## 1. Session start (Claude)
- CLAUDE.md is loaded automatically: do not re-read it, the README, CHANGELOG or big docs "for context".
- Backlog in one short command, titles only:
  `gh api "repos/odinguard009/aeterna-experiment/issues?state=open" --jq '.[] | "#\(.number) \(.title)"'`
- Open only the issue you work on (`gh api repos/odinguard009/aeterna-experiment/issues/N --jq .body`).

## 2. Reading code (Claude)
- Look the name up in `docs/ai/code-map.md` (~1.2k tokens, regenerated by every build), then `grep -n` in that part, then `Read` with `offset`/`limit` for just that function. Never read `index.html`, `build/`, `build/all-cards.json` or the card pack whole.
- Card data: query with a one-line `python3 -c` (only the fields needed), never print whole JSON.

## 3. Running things (Claude)
- Every command prints only what decides the next step: pipe through `grep -E "^not ok|^# (pass|fail)"`, `tail -3`, `--jq`. No raw logs, no full test listings.
- Work loop: `npm run -s loop` = build -> lint -> brand guard -> smoke tests + changed test files (~15 s; `-- --full` = all quick tests, ~3 min, pre-push only) in ONE tool call with a one-line result (failures print only the failing lines). `test:quick` runs every `tests/unit/*.test.mjs` except the slow ones in `tools/quick-tests.mjs`, so new test files need no `package.json` edit. Python suites only for UI flows the change touches.
- No local full regression and no local sims: GitHub runs them (dispatch, see `release.md`; 10 sims for a patch, 30 for a minor). Regression is not awaited (owner, 2026-10-18); the next session reads it. To wait for **CI** on your push use ONE command:
  `for i in $(seq 1 40); do s=$(gh api "repos/odinguard009/aeterna-experiment/actions/runs?per_page=6" --jq '[.workflow_runs[] | select(.head_sha=="'$(git rev-parse HEAD)'")] | map("\(.name):\(.status):\(.conclusion)") | join(" ")'); case "$s" in *in_progress*|*queued*|"") sleep 30;; *) echo "$s"; break;; esac; done`
  On failure read only the failing lines: `gh run view <id> --log-failed | grep -E "BAD|FAIL|Error" | head -20` (or the `last-run-*` artifact).
- Screenshots only when the UI changed, one per layout.
- A failing seed is debugged by replaying that one seed, never by rerunning many games.

## 4. Writing (Claude)
- Chat replies to the user: a few sentences, no step recaps (the task list shows progress).
- Release notes and docs: bullet points, only what changed.
- Project docs: write only the files that changed; no copies of repo data (card JSON lives in the repo only).
- Do not re-propose skills or rewrite docs that did not change.

## 5. Scope (user + Claude)
- Scope per session is decided by Claude (see CLAUDE.md "Session scope"): small tasks bundled, a heavy task alone; start each session with one complete instruction, e.g. "Kerjakan issue #1" (CLAUDE.md is loaded automatically; saying "Baca CLAUDE.md" only triggers a wasted read). Extra instructions mid-task and "stop" cause rework: send them before starting when possible.
- Model choice (owner, 2026-10-20; replaces "Opus for everything" of 2026-10-17): Opus for engine, protocol and compiler work; Sonnet for docs/cleanup and card bundles that only write effect JSON with existing actions.
- No subagents (owner, 2026-10-20) except the read-only player-view pass: the A2 pilot measured ~1 complete card per 100k tokens with card-author agents against ~8-11 for main-session bundles (v0.78.0), and team sessions spent most of their tokens in agents.
- Brainstorming chat: upload `build/aeterna-docs-pack.md` (`node tools/pack_ai.mjs --docs`, ~17k tokens), not the full code pack (~86k).

## 6. Settings (user)
- Turn off the plugins and skills this project does not use (e.g. AnimatedWebs, Revenue Grid, Data, Design, Productivity): their descriptions are loaded into every message.
- Keep the Project docs small (done in v0.30.1: card JSON copies removed, a short card list kept).
- Ask "explain usage" at the end of a session to see where the tokens went, and tell Claude what to cut next.

## 7. Ideas taken from the Aegis repo (v0.30.1)
- Progressive disclosure: CLAUDE.md holds only the rules needed on every task and routes to topic docs (`docs/ai/cards-and-rules.md`, `docs/ai/release.md`) with a reading condition; workflows live in skills, not repeated in CLAUDE.md.
- A generated code map so the code is never explored blindly.
- A pre-push hook (`.githooks/pre-push`: build check, lint, quick tests) so CI/Regression minutes and polling are not spent on broken pushes.
- Replay-first bug reproduction (already in place: seeds and `BS.runReplay`).

## 8. Lessons kept from the measurements of v0.30-v0.39 and the checks of 2026-10-14..16
Condensed in v0.69.3 (P0 B8); the full measurements stay in git history (this file before v0.69.3).
- Fixed context dominates: ~44% of a session is the system prompt, tool list and skill/plugin descriptions re-sent on every call, ~34% the growing conversation history, ~4% the work itself (v0.34 measurement, ~6.2M effective tokens in 167 calls). So: fewer calls, batched commands, one script per step, short CLAUDE.md (it is re-sent on every call; history lives in `CHANGELOG.md`).
- After the release, stop: Q&A and research in the same session cost twice the release (v0.34.0: 2.1M release, 4M afterwards). Ask several things in one message.
- A minor release costs ~1-2M effective tokens in ~60-70 calls. No call or token limit per session (owner, 2026-10-20); every commit is pushed at once, so a cut session loses at most one task. Long sessions still cost more per step (the history grows), so batch commands and keep outputs short.
- Never read `index.html` (~80k tokens) or a whole card JSON; grep + offset in the source parts, one-line `python3 -c` queries on card data (the Fandom JSON alone is ~2M tokens and once pushed the Project over its limit: card data lives only in the repo).
- Big listings are expensive: never list a laptop folder recursively; use the image index `data/index/saga_card_index.json` first. Images: contact sheets of ~20 cropped corners, one colour at a time, only unverified fields; every image is re-sent on every later call.
- Cheap guards beat repeated Regression runs: `tools/check_renames.py` in the pre-push hook catches removed names / labels still used in tests (v0.31 lost a second Regression to that); for a single-word UI text change run the suites that grep the old word.
- `add_repo` first, then one light sparse clone without `data/sources` and the big report table; never two git operations at once.
- Gates count only `v*` release commits (OVERLAP guard, backup due every 5 releases), so chore/docs commits block nothing. Idle auto-mode runs end at the gate `check` (one `gh api` call, a few thousand tokens).
- Shared mechanics once: build a mechanic several decks need in one version, not piecemeal per deck.
- Every roadmap session shows `Token awal` at the start and `Token terpakai` (budget-counter difference, not the billed figure) at the end and in a handoff; the DONE line passes `start=<Token awal> budget=<now>` and the gate computes it (item T, 2026-10-21).
- Owner-side savings: turn off unused connectors, skills and plugins in the Project (settings apply to new sessions only); keep the Project instructions short and let CLAUDE.md hold the rules (copies drift); Claude Code desktop/terminal sessions carry a smaller system prompt than the claude.ai chat.

## 9. Test cleanup (owner, 2026-10-19: "too many tests")
- Measured: the quick set had grown to 1,214 tests (~3 min) and ran at session start, after every task and in the pre-push hook; local `npm test` repeated what CI runs; Regression ran every session.
- Now: loop = smoke + changed test files (~15 s), full quick set once in the pre-push hook, no local `npm test`, Regression only when `tools/regression_due.sh` says DUE (+ weekly scheduled run), player-view pass at backups and UI changes, no new-test quotas. Details and the open proposals B1-B10: `docs/ai/process-plan.md`.

## 10. Per-step savings (owner, 2026-10-20: "lakukan itu")
No per-step measurement existed; these follow from where a card session spends its calls (estimate: build loop ~40-50%, card checks at promotion ~15-25%, end steps ~10-15%, sizing ~5-10%, start ~5%).
- **Promotion check by sample (built in v0.80.0: `node tools/promotion_sample.mjs`):** a script prints one line per promoted card (id, compiled actions, residual); main reads text vs JSON in full only for cards with a new action or condition, cards whose actions have no generator in `tests/unit/lib/fx-props.mjs`, and a random 1 in 4 of the rest (seeded, ids listed in the release notes). A wrong card found in the sample = read the whole batch.
- **Batched build loop:** write the scenario first, then all edits for one pattern, then ONE `npm run -s loop`; never edit-loop-edit-loop per sentence.
- **One end script (built in v0.80.0: `bash tools/release_docs.sh --end` after the push; the README build line comes from the build, the CHANGELOG stays hand-written):** `tools/release_docs.sh` so one call does the CHANGELOG count lines, README build line, unlock report, pack plan, mind map (when due), copies the game file to the outputs folder and runs `tools/session_end_check.mjs` (also: waits for CI on the newest commit CI runs on, not a docs-only HEAD (v0.90.0 time fix); dispatches Regression when due, pushes the backup when due, prints the counts / auto-mode / Mode hemat lines); the final steps then cost 2-3 calls instead of ~8 while the history is longest.
- **Mind map every 3rd release** (`tools/mindmap_due.mjs`; also when the plan changed); the game file is still sent every session.
- **Measure per step:** every roadmap session notes the token counter at the start and end of each step (start, sizing, research, build, promotion, end) and writes the table into its handoff / final message; after three sessions this section is replaced by the measured split.
- Kept: the pre-push full quick set (time, not tokens; it stops broken releases).
